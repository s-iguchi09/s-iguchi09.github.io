# 第 11 章 付録サンプルと記事の実測の突き合わせ

環境: .NET Framework 4.8.9363.0 / Microsoft Windows 10.0.26200

記事: [WPF で Task.Result を呼ぶと画面が固まる原因と、ConfigureAwait(false) で直らない条件](https://s-iguchi09.github.io/ja/articles/wpf-task-result-deadlock-synchronizationcontext/)。子プロセスでコマンドを UI スレッドで実行し、200 ms 後に別の処理を UI スレッドへ積んで、2.5 秒後に状態を読んだ。「待っている間に走る」は、積んだ処理が走った時点でまだ結果が出ていなかったことを示す。記事の表の「内側の await の後」の列は、サンプルに計測用のコードを入れないため比べない。

| 操作 | 記事の該当箇所 | 記事の値 | サンプルの実測 | 記事と一致 |
|---|---|---|---|---|
| 再現版、「読み込む」のコマンドを実行 | LoadAsync().Result の行 | UI スレッド: 止まったまま、積んだ処理: Pending のまま、2.5 秒後の結果: （なし） | UI スレッド: 止まったまま、積んだ処理: Pending のまま、2.5 秒後の結果: （なし） | 一致 |
| 修正版、「読み込む」のコマンドを実行 | async void の Click で await LoadAsync() の行 | UI スレッド: 止まらない、積んだ処理: 待っている間に走る、2.5 秒後の結果: 42 | UI スレッド: 止まらない、積んだ処理: 待っている間に走る、2.5 秒後の結果: 42 | 一致 |
