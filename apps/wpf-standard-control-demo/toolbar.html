ToolBar Menu

ToolBar lays out commands in a strip and moves items that do not fit into an overflow menu. Several toolbars can be arranged in a ToolBarTray.

Overview

ToolBar derives from HeaderedItemsControl. Items that do not fit are moved to an overflow popup opened by the button at the right end. This does not require a ToolBarTray. The demo app's overflow section uses a ToolBar on its own, 100 to 400 wide, and at 100 wide four of its five buttons were moved to the overflow. A tray adds bands, dragging, and locking.

Items placed in a ToolBar receive the toolbar's own styles: a Button, a ToggleButton, a ComboBox, and a Separator each had the style stored under ToolBar.ButtonStyleKey, ToggleButtonStyleKey, ComboBoxStyleKey, and SeparatorStyleKey. A Separator in a horizontal toolbar became a vertical line, 1 wide. The toolbar's own Background can be changed directly: set to LightYellow, it replaced the default #FFEEF5FD in the template's border.

The demo app has a section for each property below. The "Show Code" link under each section displays its XAML.

Demonstrated Properties

The following properties are demonstrated interactively in the WPF Standard Control Demo App. The behavior described for each one was measured on .NET 10 (see Measured Behavior).

Property Values Description
OverflowMode (ToolBar attached) AsNeeded / Never / Always Where an item goes when space runs out; the default is AsNeeded. In the demo app's arrangement, five buttons with the second one as the target, the target at width 100 went to the overflow with AsNeeded, stayed on the bar with Never, and was always in the overflow with Always, even at width 400. Never is not a way to keep everything visible: with all five buttons set to Never in a toolbar 100 wide, nothing overflowed and the buttons took 198.15, so most of them were cut off.
HasOverflowItems / IsOverflowItem (ToolBar) bool (ReadOnly) HasOverflowItems tells whether the toolbar has any item in its overflow, and the attached ToolBar.IsOverflowItem tells it for a single item. Both are read-only; the demo app shows them for the toolbar and the target button.
IsOverflowOpen (ToolBar) bool Whether the overflow popup is open. The demo app binds it to a check box. With nothing in the overflow (width 400), the overflow button was still visible but disabled. Setting IsOverflowOpen = true still opened the popup, which had no items to show.
Band / BandIndex (ToolBar) int The row of a ToolBarTray the toolbar is in, and its order in that row. In the demo app's tray, the toolbars with bands 0, 0, 1, 1 and indexes 0, 1, 0, 1 were placed at (0, 0), (147.79, 0), (0, 30.96), and (147.79, 30.96). Dragging a toolbar by its thumb changes them: the toolbar at band 1, index 0, dragged 250 to the right and 30 upward, moved to band 0, index 0.
Background / IsLocked / Orientation (ToolBarTray) Brush / bool / Orientation IsLocked is inherited by the toolbars in the tray. With True, each toolbar's thumb was collapsed, so the toolbars cannot be dragged. Orientation of the tray decides the toolbars' orientation. ToolBar.Orientation is read-only: in a vertical tray it was Vertical, outside a tray Horizontal, and setting it threw InvalidOperationException. The two cannot be out of step.

XAML Example

The following XAML is the overflow section of the demo app (ToolBarUsageControl.xaml), with the styles, the surrounding GroupBoxes, and some alignment attributes left out and the namespace declarations added. markupextensions is the prefix for the demo app's own markup extensions:

<StackPanel xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
            xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
            xmlns:markupextensions="clr-namespace:WPFStandardControlDemoApp.Common.MarkupExtensions">
  <CheckBox x:Name="IsOverflowOpenCheckBox" Content="IsOverflowOpen" />
  <ComboBox x:Name="OverflowModeComboBox"
            DisplayMemberPath="Name"
            ItemsSource="{markupextensions:EnumBindingSource EnumType=OverflowMode}"
            SelectedIndex="0" SelectedValuePath="Value" />
  <Slider x:Name="WidthSlider" Minimum="100" Maximum="400" Value="200"
          LargeChange="50" TickFrequency="50" TickPlacement="BottomRight"
          AutoToolTipPlacement="BottomRight" />

  <ToolBar x:Name="OverflowToolBar" HorizontalAlignment="Left"
           Width="{Binding Value, ElementName=WidthSlider}"
           IsOverflowOpen="{Binding IsChecked, ElementName=IsOverflowOpenCheckBox}">
    <Button Content="Item 1" />
    <Button x:Name="OverflowTargetButton" Content="Target Item"
            ToolBar.OverflowMode="{Binding SelectedValue, ElementName=OverflowModeComboBox}" />
    <Button Content="Item 2" />
    <Button Content="Item 3" />
    <Button Content="Item 4" />
  </ToolBar>

  <TextBlock Text="{Binding HasOverflowItems, ElementName=OverflowToolBar}" />
  <TextBlock Text="{Binding (ToolBar.IsOverflowItem), ElementName=OverflowTargetButton}" />
</StackPanel>

Common Use Cases

  • Application commands: new, open, and save buttons along the top of a window.
  • Formatting: toggle buttons for bold and italic, and a combo box for the font size.
  • Several toolbars: a ToolBarTray with a toolbar per group of commands, arranged in bands.

Tips and Best Practices

  • Use a ToolBarTray for bands and dragging, not for overflow. Overflow works in a ToolBar on its own.
  • Keep OverflowMode="Never" for a few items. Items marked Never are cut off rather than moved when the toolbar is too narrow.
  • Save Band and BandIndex to restore a user's layout. Dragging a toolbar changes them.
  • Set IsLocked="True" on the tray to fix the layout. It hides the thumbs of all its toolbars.
  • Style items through the toolbar's style keys. A button in a ToolBar uses the style under ToolBar.ButtonStyleKey, not the application's implicit Button style.

Measured Behavior

Every behavior on this page was measured by running it on .NET 10 / Windows 11, using ToolBarDemoScene in this site's screenshot tool. Dragging a toolbar was reproduced by raising the same DragStarted, DragDelta, and DragCompleted events on its thumb that a mouse drag raises. Sizes and positions are the values on the measuring machine.
