Grid Layout

Grid arranges its children in rows and columns. Each row and column is sized by a fixed value, by Auto (the size of its content), or by a star (*) share of the space that remains.

Overview

A Grid defines its rows with RowDefinition and its columns with ColumnDefinition, and each child picks a cell with the attached properties Grid.Row and Grid.Column (zero-based). The three sizing modes work together: in a Grid 440 wide with the columns Auto | 80 | 1* | 2* and 60-wide content in each column, the columns measured 60 / 80 / 100 / 200. The star columns split the remaining 300 in a 1:2 ratio. Widening the same Grid to 740 changed only the star columns, to 200 / 400.

Grid.RowSpan and Grid.ColumnSpan let a child cover several cells. Several children can also share one cell; they overlap, and Panel.ZIndex decides which one is in front. SharedSizeGroup aligns columns (or rows) across separate Grids, which is how form rows built as individual Grids keep their label columns the same width.

In the demo app, every property below has its own section with input controls that change the value while the result is displayed, and a "Show Code" link that shows the XAML of that section.

Demonstrated Properties

The following properties are demonstrated interactively in the WPF Standard Control Demo App. The behavior described for each one was measured on .NET 10 (see Measured Behavior).

Property Values Description
Grid.Column (attached) int Places a child in the column with this zero-based index. The default is 0, so children that omit it all land in column 0 and overlap. An index beyond the defined columns does not raise an error: the child goes to the last column. The demo app shows this, because its 2 × 2 Grid lets you choose column 2, and the text then stays in the right-hand column. A negative value throws ArgumentException.
Grid.Row (attached) int The vertical counterpart of Grid.Column, with the same rules: the default is 0, and an index beyond the defined rows places the child in the last row. In a 2 × 2 Grid, Grid.Column="5" Grid.Row="5" put the child in the bottom-right cell.
Grid.ColumnSpan (attached) int Lets a child cover this many consecutive columns, starting at its Grid.Column. A span longer than the remaining columns is cut short without an error: in a three-column Grid, Grid.Column="1" Grid.ColumnSpan="5" covered columns 1 and 2. A span of 0 throws ArgumentException.
Grid.RowSpan (attached) int Lets a child cover several consecutive rows, for example a preview panel beside a column of fields. As with ColumnSpan, a span longer than the defined rows is cut short: RowSpan="5" in a two-row Grid covered both rows.
ShowGridLines bool Draws lines along the row and column boundaries, which helps you check how cells are sized. The lines are drawn by an extra internal visual (GridLinesRenderer), and ShowGridLines is the only public property of Grid that concerns them. Their color, thickness, and style cannot be set, so use Border elements for lines that are part of the design.
Grid.IsSharedSizeScope (attached) / SharedSizeGroup (ColumnDefinition) bool / string Keeps columns that share a group name at the same width across separate Grids. Set Grid.IsSharedSizeScope="True" on a common ancestor. With 50-wide and 120-wide content, the two Auto columns measured 50 / 120 without the scope and 120 / 120 with it. A star column in a shared group behaves like Auto: it also measured 120 / 120 instead of filling the remaining space. In the demo app, the check box switches the scope on and off, and the text boxes change the content of each Grid.
Width / MinWidth / MaxWidth (ColumnDefinition) GridLength / double / double Auto fits the widest content, a number sets a fixed width, and * takes a share of the remaining width. MinWidth and MaxWidth also limit Auto columns: MaxWidth="30" on an Auto column with 60-wide content kept the column at 30. When the values conflict, MinWidth wins. The demo app starts with Width="25" MinWidth="30" MaxWidth="100", and the column is 30 wide. MinWidth="100" MaxWidth="50" gave 100. Star columns keep their ratio only when the Grid has a finite width to divide; see the tips below.
Height / MinHeight / MaxHeight (RowDefinition) GridLength / double / double The same rules apply to rows. With the demo app's starting values (Height="20" MinHeight="10" MaxHeight="100"), the row is 20 high. Height="5" MinHeight="10" gave 10, and an Auto row with MaxHeight="15" and 40-high content was 15 high. Placing Auto rows inside a ScrollViewer is not a problem: three 100-high Auto rows in a 120-high ScrollViewer made the Grid 300 high and the vertical scroll bar appeared.
Background (Panel) Brush Determines whether the empty parts of the Grid receive the mouse. With the default null, a hit test on an empty area of the Grid went through to the element behind it. With Transparent, the same hit test found the Grid. Set Transparent when the whole area should react to clicks or MouseEnter without painting a color.
Panel.ZIndex (attached) int Sets the front-to-back order of children that overlap. Without it, the child added later is in front; with ZIndex="1", the earlier child came to the front. It only compares children of the same panel: an element with ZIndex="100" inside a nested Grid stayed behind a later sibling of that nested Grid. It came to the front only after the nested Grid itself was given a higher ZIndex.

XAML Example

The following XAML is the ColumnSpan / RowSpan section of the demo app (GridUsageControl.xaml), with the styles and the surrounding GroupBoxes left out. The combo boxes are bound to the spans of the first and second text blocks:

<ComboBox x:Name="ColumnSpanComboBox" SelectedIndex="0" SelectedValuePath="Content">
  <ComboBoxItem Content="1" />
  <ComboBoxItem Content="2" />
</ComboBox>
<ComboBox x:Name="RowSpanComboBox" SelectedIndex="0" SelectedValuePath="Content">
  <ComboBoxItem Content="1" />
  <ComboBoxItem Content="2" />
</ComboBox>

<Grid x:Name="ColumnSpanRowSpanResultGrid">
  <Grid.ColumnDefinitions>
    <ColumnDefinition />
    <ColumnDefinition />
    <ColumnDefinition />
  </Grid.ColumnDefinitions>
  <Grid.RowDefinitions>
    <RowDefinition />
    <RowDefinition />
  </Grid.RowDefinitions>
  <TextBlock Grid.Row="0" Grid.Column="0"
             Grid.ColumnSpan="{Binding SelectedValue, ElementName=ColumnSpanComboBox}"
             Background="CadetBlue" Text="1x1,ColumnSpanSetting" />
  <TextBlock Grid.Row="0" Grid.Column="2"
             Grid.RowSpan="{Binding SelectedValue, ElementName=RowSpanComboBox}"
             Background="SteelBlue" Text="1x3,RowSpanSetting" />
  <TextBlock Grid.Row="1" Grid.Column="0" Background="CornflowerBlue" Text="2x1" />
  <TextBlock Grid.Row="1" Grid.Column="1" Background="LightBlue" Text="2x2" />
</Grid>

Common Use Cases

  • Data-entry forms: an Auto label column and a * input column, so the labels stay compact and the inputs take the rest of the width.
  • Application shells: a header row, a content row with a sidebar and a main area, and a footer row in one Grid.
  • Overlays: a loading indicator or message placed in the same cell as the content, brought to the front with Panel.ZIndex and shown with a Visibility binding.
  • Aligned rows built from templates: each item of an ItemsControl is its own Grid, and SharedSizeGroup keeps the columns aligned.

Tips and Best Practices

  • Star columns need a finite width. Star columns do not collapse to zero inside a StackPanel or ScrollViewer, but they can lose their ratio. In a horizontal StackPanel, 1* | 2* columns holding 60-wide and 30-wide content became 60 / 30, their content widths. A vertical StackPanel passes its width down, and the ratio held (133.33 / 266.67). In a ScrollViewer narrower than the content, the result depends on horizontal scrolling. With it enabled, the columns took their content widths and a scroll bar appeared. With it disabled, the columns kept the 1:2 ratio (20 / 40), which cut off the 60-wide content.
  • Out-of-range indices fail silently. Grid.Column, Grid.Row, and the spans are clamped to the defined rows and columns rather than rejected. After removing a ColumnDefinition, check the children that referred to it; they move into the last column without any warning.
  • A Grid without definitions is one cell. Every child fills it and overlaps the others. A child with Grid.Column="1" was still placed in that single cell.
  • Nesting Grids costs little by itself. For 500 TextBlocks, putting each row in its own nested Grid kept the first layout within about 10% of a flat Grid over repeated runs. Wrapping every TextBlock in three extra Grids, 1,500 in all, cost roughly 10–25% more. Auto columns instead of * made no measurable difference. Choose the structure that is easiest to read.
  • Auto and star can make Grid measure a child twice. In a 2 × 2 Grid whose columns are Auto, * and rows are *, Auto, the child in the Auto-column/star-row cell was measured twice on the first layout; with only fixed, only Auto, or only star definitions, every child was measured once. This matters for children whose measurement is expensive.
  • Use Background="Transparent" for hit testing on a Grid that should react to the mouse in its empty areas.

Related Controls and Articles

  • GridSplitter — lets the user resize Grid rows or columns by dragging.
  • DockPanel — docks children to the edges; enough for a window frame with few regions.
  • StackPanel — stacks children in one direction.
  • UniformGrid — makes every cell the same size without row or column definitions.
  • Why a WPF ScrollViewer does not scroll — a ScrollViewer inside a vertical StackPanel never gets a finite height, so it cannot scroll; replacing the StackPanel with a Grid fixes it.
