Label Display

Label shows a caption, usually for an input field, and can move the keyboard focus to that field with an access key.

Overview

Label derives from ContentControl. It does not take the focus itself: Focusable and IsTabStop were both False, and Tab from a TextBox before a Label went straight to the TextBox after it. Its default Padding is 5 on every side, and its content is aligned Left and Top.

A string content is shown with access keys recognized: the character after an underscore becomes the access key, and the underscore itself is hidden. The article linked below covers this, and how to show an underscore. A string with a line break is shown on two lines: the Label was 25.96 high with one line and 41.92 with two.

The demo app has sections for Target, the content, and the Control properties Padding, the font properties, Background, Foreground, the border, and the content alignment. The "Show Code" link under each section displays its XAML.

Demonstrated Properties

The following properties are demonstrated interactively in the WPF Standard Control Demo App. The behavior described for each one was measured on .NET 10 (see Measured Behavior).

Property Values Description
Target UIElement The element that receives the focus when the Label's access key is pressed. In the demo app's two pairs, _Name(Press Alt+N) and _Age(Press Alt+A), the access keys N and A moved the focus to the Name and Age text boxes. Without Target, the access key of _Plain left the focus where it was. A different focus scope is not a problem: a Label whose Target was a TextBox inside a ToolBar moved the focus into it. Target does not name the field for screen readers: the Name TextBox had an empty UI Automation name and no LabeledBy.
Content (ContentControl) object The caption. The demo app binds it to a multi-line text box, so a line break in the text gives a Label of two lines.
Padding (Control) Thickness The space around the content; the default is 5 on every side.
FontWeight / FontStyle / FontStretch / FontSize / FontFamily (Control) font values The font of the caption. The demo app has a section for each.
Background / Foreground / BorderBrush / BorderThickness (Control) Brush / Thickness The colors and the border of the Label. The demo app has a section for each.
HorizontalContentAlignment / VerticalContentAlignment (Control) HorizontalAlignment / VerticalAlignment Where the content sits inside the Label; the defaults are Left and Top.

XAML Example

The following XAML is the Target section of the demo app (LabelUsageControl.xaml), with the styles and the surrounding GroupBox left out:

<Grid>
  <Grid.ColumnDefinitions>
    <ColumnDefinition Width="auto" />
    <ColumnDefinition Width="*" />
  </Grid.ColumnDefinitions>
  <Grid.RowDefinitions>
    <RowDefinition />
    <RowDefinition />
  </Grid.RowDefinitions>
  <Label x:Name="TargetNameLabel" Grid.Row="0" Grid.Column="0"
         Content="_Name(Press Alt+N)"
         Target="{Binding ElementName=TargetNameTextBox}" />
  <TextBox x:Name="TargetNameTextBox" Grid.Row="0" Grid.Column="1" />
  <Label x:Name="TargetAgeLabel" Grid.Row="1" Grid.Column="0"
         Content="_Age(Press Alt+A)"
         Target="{Binding ElementName=TargetAgeTextBox}" />
  <TextBox x:Name="TargetAgeTextBox" Grid.Row="1" Grid.Column="1" />
</Grid>

Common Use Cases

  • Form captions: a caption next to each field, with an access key that jumps to it.
  • Captions for other controls: a ComboBox or a DatePicker as the Target.
  • Captions with content: an icon and text together, since the content can be any element.

Tips and Best Practices

  • Set Target on every caption with an access key. Without it, the key does nothing.
  • Name the field for screen readers separately. Target did not give the TextBox a name; set AutomationProperties.Name or AutomationProperties.LabeledBy on the field.
  • Use a TextBlock for text that needs no access key. The article linked below measures what many Labels cost.

Measured Behavior

Every behavior on this page was measured by running it on .NET 10 / Windows 11, using LabelDemoScene in this site's screenshot tool. Access keys were sent through AccessKeyManager.ProcessKey, which handles a key pressed with Alt, and Tab through WPF's input manager, the same path as keys typed on a keyboard. Sizes are the values on the measuring machine.
